# Independent Section 4 source review

Reviewed 2026-09-26 against the [live App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) and the private source catalog. The 110 Section 4 source-fragment IDs are all represented in `references/obligations/4.json`; no missing source fragment was found. The findings below concern applicability and exception semantics. This report contains no source prose.

## Findings

1. **High — 4.2 subtype applicability is too broad.** Every 4.2.x obligation inherits the condition `Every submitted app; apply the narrower AR, template, or remote-desktop conditions where relevant.` That condition does not itself restrict `atom-1868742025354677afbcfe25351860cc` to ARKit apps, the three 4.2.6 obligations to commercial-template apps/services, or the eleven 4.2.7 obligations to clients mirroring particular host applications instead of an unrestricted device. It also leaves the two 4.2.3(ii) atoms without an explicit initial-launch resource-download predicate. Set each atom's `applicability.condition` to its actual trigger, with the 4.2.7 distinction expressed explicitly. Otherwise an attestation or coverage report can ask every app to satisfy remote-desktop and template rules.

2. **High — 4.8 exceptions are only attached to the parent parity atom.** The five exception IDs are in `atom-d5340126eb1e44d1bc17f2d2d40daaeb.exceptions`, but not in the three required alternate-service property atoms `atom-d0280e2be689410ab9ee1b606d8bd1b4`, `atom-239d3f04fa454852bd326b2388f6994d`, and `atom-57af4e2c851143f0a5fe5a1421dcb808`. If an exception applies, the entire alternate-service requirement is waived, including its three properties. Link the exceptions to those three atoms or model them as conditional children whose applicability follows the parent decision. Keep the source/semantic login routes partial until that condition is established.

3. **Medium — 4.4 extension subtype applicability is under-specified.** All 4.4.1 keyboard and 4.4.2 Safari extension obligations use the same broad condition as generic extension rules. Narrow the eight 4.4.1 obligations to apps with keyboard extensions and the five 4.4.2 obligations to apps with Safari extensions, while retaining the general 4.4 condition for any extension. This matters when the report asks for evidence or computes `NOT_APPLICABLE`.

4. **Medium — the 4.2.7(d) mirrored-transaction exception has no paired payment rule.** `atom-ce0ef87e6f5c40c6ae24083839137ffc` is classified as an exception but only links to its source fragment. It qualifies in-app purchase treatment for transactions completed on the host device, so connect it to the relevant Section 3.1 payment obligation(s), or record an explicit cross-section relationship that the decision engine can use. It must not be read as a general exemption for purchases initiated or processed in the client.

5. **Low — 4.5.1 approved-feed permission is detached.** `atom-6373c0202be34e0ba90bd8948283c332` has kind `exception` but no relationship to either 4.5.1 prohibition atom. Clarify it as a narrow allowed input method and link it, if applicable, only to `atom-d5429e6aa0b14c9da0fab53a0a821415`. It does not waive the separate rule against rankings made from Apple-site information (`atom-218085b57ed7404fbd7277dbb662eeca`).

The existing 89 empty routes are implementation gaps for Wave 2, not source-classification omissions. Existing partial routes were not counted as conclusive proof of compliance.
