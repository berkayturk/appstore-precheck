# Independent source review: Section 5

Source: [Apple App Review Guidelines, Section 5](https://developer.apple.com/app-store/review/guidelines/#5), checked 2026-09-26. Compared all 146 private source fragments for 5.x with the 327 public records in `references/obligations/5.json`; every source fragment ID is represented. Findings below concern the atom criteria, links, and route semantics. This report contains no source prose.

## Findings

1. **5.1.1(viii), narrowed data-source prohibition.** `atom-7cb28983fd1b400a97da56fdf9f7c6da` allows compiling personal information from an indirect source whenever the person consents. The source treats indirect collection and missing consent as separate disqualifying conditions, including for public databases. Restore both conditions in the criterion; an attestation should test source provenance and consent separately. Source fragment: `req-5e8400baee554214aab82b5d38f44058`.

2. **5.1.1(ii), legal-basis exception is not linked.** `atom-e3c314310e024e5298cd8539cc8ee3c8` states an unconditional collection-consent criterion, while `atom-ce94405f21d247f8855d6a6dbe2869a3` separately addresses legitimate-interest collection without consent. The former has no exception link, so a valid documented legal basis could be incorrectly failed. Model a narrow, law-specific exception and link it to the consent atom; keep a distinct question about satisfying every condition of that law. Source fragments: `req-2ed8f6c0f15e48ccb859311cf79b2af9`, `req-52f14863aefc46c48acb8417878ef66a`.

3. **5.1.3(i), direct-benefit allowance loses two conditions.** `atom-11db63a9d44443c6ab6e0a88e3eacfc3` is an unlinked exception that mentions only a direct benefit. The same source passage also makes the provider's own submission and lack of onward sharing necessary; these were classified as disconnected definitions `atom-5428457075704d9380e0b77dd56e167d` and `atom-8dab1547f1934f7fa816c63312c62158`. Combine all three conditions in the exception and link it to the affected data-use rule, or promote the conditions to linked obligations. Source fragment: `req-45d1ab7f607a45329dafab591f3365d9`.

4. **5.5, configuration-profile scope is lost.** `req-e2b31e4bcc694fe59cdc6e7ff40d80bb` is represented only by definition `atom-1f300eb9147146dcb1af6ce08da28a72`; the eight 5.5 obligations use an MDM-service feature condition. An app offering configuration profiles without an MDM service could thus skip this entire requirement set. Extend applicability for relevant 5.5 atoms to configuration-profile apps, and make the scope link machine-readable.

5. **5.1.1(v), social-network core-function rule is underspecified.** `req-5c35d3def51348d48f5acb49ebd035dd` is informational with no relation to `atom-97d112fa95e74e209e31bf4ab46b2917`. This source fragment excludes ordinary profile retrieval, sharing, and invitation features from the core-function exception. Attach it as a definition or make that exclusion explicit in the criterion/attestation, so those features alone cannot justify mandatory social sign-in.

6. **Existing source checks are mapped as partial decisions when they only detect scope.** `atom-99e6360448f44c4eb98c1d6666b10b6d` maps the in-app privacy-link obligation to `support-privacy-url`, which scans fastlane URL metadata but never inspects an in-app link. `atom-05ddad1ca9ff409f92c7a87ae64473a1` maps MDM-capability approval to `mdm`, which detects code/plist signals but cannot verify approval. All seven `5.3.4` atoms (`atom-bf59fd54e04c4661a6a4dcbb248357af`, `atom-9b377905684f459fbbf35cef4a81a4b1`, `atom-2a8d143171424611a2ad06c9912de8c1`, `atom-9c54d5fd9e0547e3b0591c744198766a`, `atom-d4e0b637d3684d8db3ab8e803d6be810`, `atom-f48da7fed9d84582a76a058d068a0f43`, `atom-cf5b8329d8674d7ba0887cd89036a335`) map to `realmoney-gambling`, which only detects gambling terms in metadata. Remove these decision routes, or mark them as applicability hints that cannot satisfy the obligation; add evidence-bearing routes for the actual criteria.

7. **5.4/5.5 data restrictions are narrowed to selected data and purposes.** `atom-fa591b0a5a0a46c7b4065a857dc24730`, `atom-c2e46b4ee9a24f2494b96b9e2657ddbc`, `atom-f1e2d49b361e4aa2bd28d71508586fd8`, `atom-1c570ec994cd459facac23fe6583a1a2`, `atom-0d5d7c64c4a9440994be9ba845e06ac0`, and `atom-d0d728497c3a44908d4742c6c793e704` replace the source's broad data-use restrictions with narrower labels such as VPN-user or managed-app data and unspecified separate purposes. Preserve the source scope in the criteria; evaluate any operational interpretation through human legal review rather than silently narrowing it. Source fragments: `req-a0cab9ce192146e99d118c6da1a767f2`, `req-c3e33eff995b4db5ac06ee436244228b`.

8. **5.6.4 criterion adds a required action to a discretionary quality signal.** `atom-272cc4613bd9fafd09e58bcf425d944e` requires investigation of sustained complaint/refund patterns. The source presents those patterns as possible quality evidence, not a fixed investigation duty or threshold. Keep the quality concern but express this as a reviewer signal or suggested evidence, without an automatic failure criterion. Related source fragments: `req-7a4682a1b52d4dde8b7b46f1b3bbe9c1`, `req-fae9e7a7864a479cbdd0acab030192c8`.

## Review scope

The remaining unmapped 5.x obligations are expected Wave 2 implementation gaps rather than missing source material. The unlinked 5.4 approved-provider allowance (`atom-a5f71d4d7a374e21b35fe129c991d627`) is a separate permission for qualifying non-VPN products to use the VPN API, so it need not override the VPN-service rule.
